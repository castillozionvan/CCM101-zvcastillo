# Mission Reflection: The Cloud Data Engineer

<p align="justify">
In this laboratory activity, I gained hands-on experience as a cloud data engineer by learning why object storage is the industry standard for modern web applications. Object storage is significantly better suited for storing millions of user photos than traditional block storage because it uses a flat namespace with unique object keys rather than rigid, deeply nested file directory trees or fixed physical blocks. Block storage causes operating system file system tables to suffer severe performance degradation as file counts grow into the millions, whereas object storage scales out virtually infinitely by attaching custom metadata directly to each photo object for fast access over HTTP/S. Deploying our MinIO server using Docker made this setup seamless because it eliminated the need to manually install dependencies, configure environment paths, or set up background services on the host system; a single docker run command pulled the complete image and launched both the S3 API and Web Console ports instantly. Through this setup, I learned that a "bucket" in cloud storage serves as a top-level logical container to group objects, acting as a flat namespace boundary where access policies, security settings, and encryption rules are managed. I also realized how enterprise companies protect this data from physical server crashes by using multi-datacenter replication and erasure coding, which mathematically splits and distributes data chunks across multiple physical drives so missing files can be reconstructed on the fly without service downtime. Overall, working through these steps in the Linux terminal has greatly boosted my confidence in running containers, handling port forwarding, and using commands like docker ps to manage cloud resources effectively.
</p>
